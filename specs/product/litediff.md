# LiteDiff 产品规范

- Status: Accepted
- Version: 1.0
- Last updated: 2026-11-06
- Owner: LiteDiff maintainers
- Scope: 当前发布的 macOS 与 Windows 桌面应用

本文档是 LiteDiff 当前产品行为的基线。除非另有说明，本规范中的“必须”都是可验证的产品契约。行为变化必须通过 `specs/changes/` 记录并同步更新本文档。

## 1. 产品目标

LiteDiff 是一个本地优先的文本和代码差异比对桌面应用。它必须：

- 在常见文件和仓库规模下快速显示可靠的行级差异。
- 对修改行提供有用的词级高亮，而不是逐字符噪声。
- 在大文件和长结果集下保持有界内存、可预测退化和可操作警告。
- 让用户无需上传内容即可比较粘贴文本、本机文件和 Git 版本。
- 在 macOS 与 Windows 上保持一致的核心工作流。

## 2. 非目标

当前产品明确不提供：

- 三方合并、冲突解决或补丁应用。
- 真正的二进制、图片、PDF 或 Office 文档差异；非 UTF-8 文件只提供只读预览。
- 云同步、账号、遥测、远程 Git 操作或把文档发送到网络。
- 在虚拟滚动行内直接编辑，或逐块“采纳更改”。
- 对任意大文件的分块流式比较。
- 对仓库自定义 filter、hook、pager、fsmonitor、external diff 或签名程序的无约束执行。

## 3. 术语

| 术语 | 定义 |
|---|---|
| Side | 比较的一侧，包含文本、显示标签、可选路径、Git 来源和可选保存能力 |
| Session | 两侧文档、差分结果、选项、警告和内容标识的完整快照 |
| SessionUpdate | 省略未变化源文档的增量会话更新 |
| Source row | `DiffResult.rows` 中的对齐行索引 |
| Display index | 折叠和换行投影后的可视项索引 |
| Unified index | 统一视图中按物理行展开后的索引 |
| Fold | 将长未变动 hunk 折叠成一个摘要条 |
| Document capability | 后端签发、允许保存某个文档的不可伪造句柄 |
| Approximate | Myers 工作预算耗尽后的确定性近似结果 |

## 4. 输入、文件与保存

### 4.1 输入

| ID | 要求 | 验收 |
|---|---|---|
| REQ-IN-01 | 用户可以向任一侧粘贴文本，或把单个文本文件拖放到任一侧。 | 两侧都出现对应标签和内容；空侧可以独立存在。 |
| REQ-IN-02 | 用户可以通过原生选择器选择文件和仓库。 | 后端发起原生对话框；渲染进程不能自行扩大文件访问范围。 |
| REQ-IN-03 | 拖入文件夹时，可以使用其中第一个可读取的文本文件并提示文件总数；空文件夹给出明确提示。 | 文件夹路径不会直接成为保存能力。 |
| REQ-IN-04 | 每个文档最多 16 MiB、200,000 行。 | 超限时拒绝比较并返回可理解的限制信息。 |
| REQ-IN-05 | UTF-8 BOM 在保存后保留；CRLF 与 LF 在比较时等价。 | BOM 测试、CRLF/LF 测试通过。 |
| REQ-IN-06 | 非法 UTF-8 使用 lossy 方式预览，并保持只读。 | UI 显示只读原因，任何保存请求都被后端拒绝。 |
| REQ-IN-07 | 文档内容、设置和历史不得被上传，也不得引入隐式网络请求或遥测。 | 依赖与运行路径审查无网络调用。 |

### 4.2 保存

| ID | 要求 | 验收 |
|---|---|---|
| REQ-SAVE-01 | 显示路径不等于保存能力；只有后端登记且未过期的 `documentId` 可以保存。 | 未登记路径、历史恢复内容和伪 token 均不能写盘。 |
| REQ-SAVE-02 | 保存必须同目录原子替换，保留原 Unix 权限，并保留 BOM。 | 权限、BOM、临时文件和失败清理测试通过。 |
| REQ-SAVE-03 | 保存前后都校验摘要；文件被外部修改时必须拒绝覆盖。 | 摘要冲突与并发保存测试通过。 |
| REQ-SAVE-04 | 符号链接、路径逃逸、lossy 内容和过期能力不得保存。 | 对应安全测试通过。 |
| REQ-SAVE-05 | 两侧都有有效能力时，`Cmd/Ctrl+S` 同时保存两侧；历史版本侧永远只读。工作区与历史版本比较时，只能保存持有有效能力的工作区文件，不得创建或改写历史对象。 | 历史侧没有保存能力；工作区侧可保存时只更新工作区文件，UI 显示明确状态。 |

## 5. 差分引擎

### 5.1 行级比较

| ID | 要求 | 验收 |
|---|---|---|
| REQ-DIFF-01 | 行级比较使用线性空间 Myers，匹配必须是真相等。 | 结果可由两侧源行重建，匹配不伪造。 |
| REQ-DIFF-02 | 空文档没有虚拟尾行；尾换行不产生额外空行；孤立 CR 保留为内容。 | `source.rs` 单元测试通过。 |
| REQ-DIFF-03 | 默认比较精确匹配；支持忽略首尾空白、忽略全部空白和忽略大小写。 | `intern.rs` 和引擎集成测试通过。 |
| REQ-DIFF-04 | 忽略首尾空白只裁剪行首尾；忽略全部空白移除所有 whitespace 字符。 | 两种模式互不混淆。 |
| REQ-DIFF-05 | 忽略大小写使用 Unicode lowercase 归一化。 | 大小写测试和词级测试一致。 |
| REQ-DIFF-06 | 对修改块先配对为 `Modify` 行，再在不足处补占位行；删除/插入不得伪装成修改。 | 对齐、补位和重建测试通过。 |
| REQ-DIFF-07 | 行级搜索最多执行 25,000,000 次工作探测。预算耗尽时返回确定性近似结果并设置 `approximate=true`。 | 预算测试通过，UI 显示警告。 |
| REQ-DIFF-08 | 相同输入和选项必须产生相同结果。 | 确定性测试通过。 |

### 5.2 词级高亮

| ID | 要求 | 验收 |
|---|---|---|
| REQ-INTRA-01 | 修改行可以在 token 级高亮，标识符、下划线、驼峰、数字、Unicode 和空白不得拆坏。 | `token.rs` 测试通过，segment 可重建原文。 |
| REQ-INTRA-02 | 高亮字符偏移必须连续、按字符计数，并且不切断 Unicode 标量。 | 偏移和 Unicode 测试通过。 |
| REQ-INTRA-03 | 任一行超过 2,048 个字符或 token 时退化为整行高亮；token 搜索另有 5,000,000 探测预算。 | 上限测试通过，不退化为无界搜索。 |
| REQ-INTRA-04 | `ignore_case` 必须同时影响行级和词级判定，避免行被判等但仍有高亮。 | 大小写一致性测试通过。 |
| REQ-INTRA-05 | 用户可以关闭词级高亮；关闭后修改行仍显示行级着色。 | 引擎与设置测试通过。 |

## 9. 比较历史

| ID | 要求 | 验收 |
|---|---|---|
| REQ-HIST-01 | 开启历史记录时，每次非空比较按内容标识去重后保存到本机应用数据目录。 | 不保存空比较，切换选项不重复记录同一内容。 |
| REQ-HIST-02 | 恢复历史会产生新的只读快照标签；历史路径不得直接重新获得保存能力。 | 恢复后无有效 `documentId`。 |
| REQ-HIST-03 | 历史按今天、昨天或日期分组；支持单条删除和全部清空。 | 前端分组与后端删除测试通过。 |
| REQ-HIST-04 | 默认保留 7 天和 100 条；天数与条数可分别配置，`0` 表示关闭该规则。 | 保留策略测试通过。 |
| REQ-HIST-05 | 单条历史最大 4 MiB；超限时不保存，不得截断成另一份比较。 | Rust 与前端上限测试通过。 |
| REQ-HIST-06 | 历史 ID 只能使用安全文件名字符；损坏的 sidecar 或正文被隔离，不得影响其他条目。 | 历史安全、兼容和损坏隔离测试通过。 |
| REQ-HIST-07 | 历史写入必须原子化，并发保存不得互相覆盖，旧格式必须可读。 | 并发、legacy 和原子写测试通过。 |

## 11. 快捷键

Windows 上 `Ctrl` 对应 macOS 的 `Cmd`。

| 快捷键 | 行为 |
|---|---|
| `Cmd+]` / `Cmd+[` | 下一个 / 上一个差异 |
| `Cmd+D` | 切换分栏 / 统一视图 |
| `Cmd+Shift+W` | 切换忽略首尾空白与换行 |
| `Cmd+Alt+E` | 展开 / 折叠全部未变动区块 |
| `Cmd+F` | 打开当前比较的查找 |
| `Cmd+S` | 保存所有有有效能力的侧 |
| `Cmd+T` / `Cmd+N` | 新建标签并回到粘贴首页 |
| `Cmd+W` | 关闭当前标签 |
| `Cmd+,` | 打开 / 关闭设置 |
| `Cmd+G` | 打开 / 关闭 Git 面板 |
| `Cmd+Y` | 打开 / 关闭比较历史 |

快捷键变化属于用户可观察行为，必须同步更新本文档和两种 README。

## 12. 安全与隐私不变量

以下要求是不可降级的发布门槛；详细编号见 [`docs/sdd/security-and-performance.md`](../../docs/sdd/security-and-performance.md)。

| ID | 不变量 |
|---|---|
| REQ-SEC-01 | 渲染进程输入一律视为不可信。路径、Git revision、历史 ID、IPC 数据和能力令牌必须在后端验证。 |
| REQ-SEC-02 | 所有文件读取与写入都受路径授权、canonicalize、符号链接和边界检查约束。 |
| REQ-SEC-03 | 保存必须验证 backend-issued capability、摘要和原子替换，不得由 UI 承诺安全。 |
| REQ-SEC-04 | Git 操作不得执行仓库控制的 hook、filter、fsmonitor、pager、external diff 或签名程序。 |
| REQ-SEC-05 | Tauri capability 只授予完成当前功能所需的最小权限。 |
| REQ-SEC-06 | 文档、历史、仓库内容和设置不离开本机；新增网络能力必须单独进行隐私评审。 |

## 13. 性能预算

性能下降不是“可接受的实现细节”；当输入达到预算边界时，产品必须保持可解释和可恢复。

| ID | 预算 |
|---|---|
| REQ-PERF-01 | 行级 Myers 峰值辅助内存为 `O(N+M)`，工作探测上限 25,000,000。 |
| REQ-PERF-02 | 单文档 16 MiB、200,000 行；超限拒绝。 |
| REQ-PERF-03 | 词级分析上限为 2,048 字符/ token，内部探测上限 5,000,000。 |
| REQ-PERF-04 | 搜索结果上限 50,000；Git 文件列表上限 20,000；提交历史上限 500。 |
| REQ-PERF-05 | Git 标准输出上限 32 MiB，标准错误上限 1 MiB；历史条目上限 4 MiB。 |
| REQ-PERF-06 | 分栏和统一视图只渲染视口 + overscan；滚动和输入事件不得扫描全文。 |
| REQ-PERF-07 | 修改选项时优先返回 `SessionUpdate`，不得为了换一个布尔选项重复传输两篇全文。 |
| REQ-PERF-08 | 所有近似、截断或退化必须确定性、有界，并在 UI 或验证记录中说明。 |

完整门禁见 [`scripts/verify.sh`](../../scripts/verify.sh) 和 [`docs/sdd/quality-gates.md`](../../docs/sdd/quality-gates.md)。

## 16. 已知限制

以下限制是当前确认接受的产品边界，不是隐含承诺：

- 没有自动化真实窗口 E2E；部分 Svelte 交互依赖源码布局断言和人工验证。
- 没有持续性能阈值基准；现有性能测试主要防止复杂度回归。
- macOS 安装包未公证；Windows 需要 WebView2。
- 语法高亮是轻量词法近似，不保证与语言编译器或完整 grammar 一致。
- 超大文件仍需整文件读入，不做流式分块。
- Git 只保证本地浏览、比较和本地分支切换；不负责 fetch、pull、push 或远端凭据。
- 行内视图和分栏视图共享折叠，但还没有逐行“接受更改”工作流。

新增限制必须说明原因、用户可见行为、替代路径和后续风险；移除限制必须通过相应变更验证。

## 17. 变更规则

- 任何影响上述要求、预算、限制或安全边界的改动都必须建立 `specs/changes/`。
- 行为变化必须在同一 PR 更新本文档；不得在下一次发布时补写。
- 本文档不接受“可能会实现”的能力；未来计划放在变更规范或 roadmap 中。
- 如果实现与本文档冲突，PR 不能以“代码已经这样工作”为由跳过评审。
