# 风险清单

严重度：S1 数据损坏或安全问题；S2 核心行为错误；S3 明显回归或维护成本；S4 文档和流程风险。

| ID | 风险 | 严重度 | 可能性 | 现有控制 | 需要的 SDD 动作 |
|---|---|---|---|---|---|
| R-01 | 规范与实际代码漂移 | S3 | 高 | 本次引入 product spec 与变更规范 | 行为变化必须同 PR 更新产品规范 |
| R-02 | `App.svelte`、`GitPanel.svelte` 等大组件继续膨胀 | S3 | 高 | 现有模块化和注释 | 新逻辑优先下沉到纯函数模块并补测试 |
| R-03 | Rust/TypeScript IPC 字段或命名不一致 | S2 | 中 | `serde(rename_all)`、类型检查和契约测试 | 跨边界改动必须有配对测试 |
| R-04 | 路径授权或保存能力回归 | S1 | 中 | `documentId`、canonicalize、symlink 拒绝、摘要校验 | 安全边界变更必须完整 SDD + 威胁检查 |
| R-05 | Git 执行仓库控制的程序 | S1 | 中 | hooks/fsmonitor/filter/gpg 硬化及测试 | 新命令必须证明不会执行仓库代码 |
| R-06 | 原子保存引入数据丢失或权限变化 | S1 | 中 | 同目录临时文件、摘要、BOM、权限复制 | 保存路径修改必须覆盖失败回滚和权限测试 |
| R-07 | 历史文件损坏或格式不兼容 | S2 | 中 | sidecar 校验、逐条隔离、serde default | 格式变化必须提供迁移和旧数据测试 |
| R-08 | Myers 预算退化被误报为精确 diff | S2 | 低 | `approximate` 标志、工作预算 | 修改算法或预算必须保留最优性 oracle |
| R-09 | 显示索引与源行索引混用 | S2 | 高 | 独立投影函数和大量视口测试 | 任何导航/搜索/折叠改动列出坐标契约 |
| R-10 | 大文件或搜索导致 UI 冻结 | S2 | 中 | 文档上限、50k 搜索上限、虚拟滚动 | 性能敏感改动提供投影/扫描基准证据 |
| R-11 | 七语言键或占位符漂移 | S3 | 中 | 全键和占位符测试 | UI 文案改动必须运行 i18n 测试 |
| R-12 | 仅靠源码字符串测试，缺少真实 UI/E2E | S3 | 高 | 纯逻辑测试较完整 | 关键交互增加打包冒烟或 E2E 计划 |
| R-13 | macOS/Windows 文件系统差异 | S2 | 中 | 平台条件编译、测试和发布构建 | 文件、路径、权限改动记录跨平台验证 |
| R-14 | 发布工作流权限或依赖漂移 | S1 | 中 | Action SHA 固定、最小权限、草稿发布 | 发布变更走 L3 并附回滚方案 |
| R-15 | 旧 `STEP*.md` 被误当作当前需求 | S4 | 中 | 文档索引声明为历史材料 | AGENTS 和文档索引持续提示 |
| R-16 | 文档模板过重导致绕开流程 | S4 | 高 | 分级变更路径 | 允许 trivial/bugfix 轻量路径，只对复杂改动强制全套 |

## 优先修复顺序

1. 保存能力、Git 执行面、历史文件等 S1 边界。
2. Myers 最优性、坐标系统、IPC 契约等 S2 核心行为。
3. 大组件拆分、E2E 和跨平台验证等 S3 工程能力。
4. 文档索引、模板体验和历史文档治理等 S4 流程问题。

## 当前已知测试空档

- 没有自动化真实窗口 E2E 测试，部分 Svelte 交互靠源码布局断言和人工验证。
- 没有持续运行的性能阈值测试；现有 `render-perf.test.ts` 主要防止算法复杂度回归。
- macOS/Windows 文件权限、ACL、xattr 和安装器行为只在对应平台的部分测试或人工流程中覆盖。
- 没有模糊测试或长时间随机差分压力测试。
- 没有 PR 级别 CI；当前 `release.yml` 只在标签或手动触发时执行完整验证。

这些空档不阻塞本次 SDD 落地，但应在后续变更中按风险逐步补齐。
